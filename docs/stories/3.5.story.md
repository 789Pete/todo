## Status: Done

## Story

**As a** user,
**I want** the network graph seamlessly integrated with my task lists and filters,
**so that** I can use both visual and traditional views as needed.

## Acceptance Criteria

1. Graph view toggle button accessible from all main task views
2. Current filter state reflected in graph highlighting and node visibility
3. Graph view respects active tag filters and shows filtered relationships
4. Smooth animated transitions between graph view and list view
5. Graph view maintains sort preferences and completion status filters
6. Split-screen mode showing graph and filtered task list simultaneously
7. Graph view state persists across user sessions and page refreshes

### Filter State Mapping (Task List → Graph)

| Task List Param | Graph URL Param | Notes |
|---|---|---|
| `?status=todo` | `?filter_status=todo` | Direct mapping |
| `?status=in_progress` | `?filter_status=in_progress` | Direct mapping |
| `?status=done` | `?filter_status=done` | Direct mapping |
| `?status=active` | *(omit)* | `active` is not a valid value for `filter_status` in `graph_builder.py` — do not pass it |
| `?tags=<uuid>` | `?filter_tag=<tag_name>` | Use `active_tags.0.name` from template context; graph builder filters by `tags__name__iexact` |
| Multiple `?tags=` | `?filter_tag=<first_tag_name>` | Graph API only supports a single `filter_tag`; silently use first active tag |

**Why tag name, not UUID?** `graph_builder.py` line 49: `tasks = tasks.filter(tags__name__iexact=filter_tag)` — it accepts a tag **name** string. The task list template has `active_tags` in context (QuerySet of Tag objects with `.name`). Access the first element as `{{ active_tags.0.name }}`.

```python
class GraphView(LoginRequiredMixin, TemplateView):
    template_name = "visualization/graph.html"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['graph_params'] = self.request.GET
        return context
```

### localStorage Persistence (AC7)

Insert in `graph-viewer.js` right after the existing block at lines 14–21:

```javascript
// AC7: Persist filter state across sessions
if (graphParams.toString()) {
    localStorage.setItem('graph_filters', graphParams.toString());
} else {
    var savedFilters = localStorage.getItem('graph_filters');
    if (savedFilters) {
        var restoredParams = new URLSearchParams(savedFilters);
        ['filter_tag', 'filter_status'].forEach(function (key) {
            var val = restoredParams.get(key);
            if (val) graphParams.set(key, val);
        });
    }
}
```

The existing line `if (graphParams.toString()) { apiUrl += '?' + graphParams.toString(); }` already handles the API URL construction — no change needed there.

### Testing Notes

[Source: `docs/architecture/testing-strategy.md`]

- JS-only behaviour (localStorage save/restore, dynamic toggle button href construction) cannot be tested by pytest — mark as manual verification
- The iframe `src` in `split.html` is a same-origin request; session cookie is shared automatically — no special auth handling needed in tests
- The iframe renders the full `task_list.html` page including navbar and footer — this is intentional for the MVP implementation; do not attempt to create a partial/iframe-safe template variant
- Test the `split-view` URL in the same `test_views.py` file as the existing `TestGraphView` tests

```python
@pytest.mark.django_db
class TestSplitView:
```
