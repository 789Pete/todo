## Story

**As a** user,
**I want** the application to provide optimal experiences across all device types,
**so that** I can maintain productivity regardless of my current device.

## Scope Notes

**PRD AC7 (offline data access):** Deferred. Full offline access requires service worker caching of API responses, offline edit queuing, and conflict resolution — well beyond a single story. This story implements web app manifest + minimal service worker to achieve PWA installability only. Offline data sync is a post-MVP infrastructure concern.

**PRD AC3 (tablet-specific layouts):** Scoped to CSS breakpoint improvements only. Bootstrap 5.3 already provides a strong responsive grid; this story adds a 2-column task card layout on `md` screens and minor form layout tweaks — no custom tablet UI framework.

**PRD AC2 (touch graph gestures):** vis-network already handles pinch-zoom and touch pan natively (`interaction.zoomView` + `dragView` are enabled, canvas has `touch-action: none`). This story adds long-press → context menu for touch devices, which replaces the desktop right-click menu on mobile.

This story covers all 7 PRD ACs with the scope boundaries above.

## Acceptance Criteria

1. A floating action button (FAB) `+ New Task` appears on small screens (≤768px) fixed to the bottom-right corner; it links to `task-create` and is hidden via `d-md-none` on tablet/desktop where the regular button remains
2. Touch devices receive a `touch-device` CSS class on `<body>` (set in `base.js` via `navigator.maxTouchPoints > 0`); keyboard shortcut hint text (`.kb-hint`) hidden on touch via CSS
3. Long-press (≥500ms) on a task or tag node in the graph opens the existing `#graph-context-menu` at the touch point, matching the right-click experience on desktop
4. Task list renders in a 2-column card grid on `md` (768px–991px) screens using Bootstrap's `col-md-6` within the existing `row` wrapper; single column on xs/sm and lg+
5. Page headings use `clamp()`-based fluid typography: `font-size: clamp(1.25rem, 3vw, 1.75rem)` applied via `.page-heading` utility class; all `<h1>` elements on main pages gain this class
6. An offline indicator banner (non-dismissible, `alert-warning`) appears at the top of `<main>` when `navigator.onLine` is `false` or the `offline` event fires; it auto-hides on the `online` event
7. A `manifest.json` is served at `/manifest.json` and referenced in `<head>` with `<link rel="manifest">`; `manifest.json` declares `name`, `short_name`, `start_url`, `display: "standalone"`, `theme_color`, `background_color`, and at least one icon; a minimal service worker is registered from `/service-worker.js` to satisfy browser install eligibility

### Service Worker & Manifest Serving Architecture

Service workers must be served at the same origin and at the path level of the scope they control. To control all of `/`, the service worker file must be accessible at `/service-worker.js` (not `/static/js/service-worker.js`).

**Recommended approach:** Add two simple Django views:

```python
# todo_project/pwa_views.py
import json
from django.http import HttpResponse
from django.conf import settings

def service_worker(request):
    with open(settings.BASE_DIR / 'static' / 'js' / 'service-worker.js') as f:
        body = f.read()
    response = HttpResponse(body, content_type='application/javascript')
    response['Service-Worker-Allowed'] = '/'
    response['Cache-Control'] = 'no-cache'
    return response

def web_manifest(request):
    with open(settings.BASE_DIR / 'static' / 'manifest.json') as f:
        body = f.read()
    return HttpResponse(body, content_type='application/manifest+json')
```

Register in `todo_project/urls.py` before `static()` patterns:
```python
from todo_project import pwa_views
path('service-worker.js', pwa_views.service_worker, name='service-worker'),
path('manifest.json', pwa_views.web_manifest, name='web-manifest'),
```

**Important**: These views read from `static/` (source), not `staticfiles/` (collected). This is fine because both dev and production have `BASE_DIR/static/` available. In production, WhiteNoise serves `staticfiles/` but these views bypass that and serve directly from the source tree. If `collectstatic` copies to `staticfiles/`, you can switch to reading from there; but reading from `static/` keeps it simple for MVP.

### Touch Long-Press Implementation

```javascript
// In initializeGraph(), after existing event handlers:
var longPressTimer = null;
var LONG_PRESS_MS = 500;

container.addEventListener('touchstart', function(e) {
    if (e.touches.length !== 1) return;
    var touch = e.touches[0];
    var rect = container.getBoundingClientRect();
    var canvasX = touch.clientX - rect.left;
    var canvasY = touch.clientY - rect.top;
    var nodeId = network.getNodeAt({ x: canvasX, y: canvasY });
    if (!nodeId) return;
    longPressTimer = setTimeout(function() {
        showContextMenu(touch.clientX, touch.clientY, nodeId);
    }, LONG_PRESS_MS);
}, { passive: true });

container.addEventListener('touchend', function() {
    clearTimeout(longPressTimer);
});
container.addEventListener('touchmove', function() {
    clearTimeout(longPressTimer);
});
```

Note: `{ passive: true }` on touchstart is required because vis-network sets `touch-action: none` via CSS — the passive listener does not interfere with vis-network's own touch handling.

## Risk and Compatibility

- **Service worker cache invalidation**: The `CACHE` version key in `service-worker.js` must be bumped manually when static assets change significantly. For MVP this is acceptable; add a note in the file.
- **PWA install eligibility**: Chrome/Edge require manifest + HTTPS + service worker. PythonAnywhere provides HTTPS via Let's Encrypt — eligibility criteria are met. Safari on iOS shows its own install prompt (Add to Home Screen) without explicit in-app prompt handling; no additional code needed.
- **Long-press conflicts with vis-network**: The `touchstart` listener uses `{ passive: true }` to avoid blocking vis-network's internal touch handling. The `clearTimeout` on `touchmove` prevents accidental context menu during pan. Test on a physical mobile device to confirm no interference.
- **Task list 2-col on md**: If drag-and-drop reordering (from an earlier story) uses a linear list assumption, the 2-col layout may break drag target ordering. Review drag-and-drop implementation before applying the grid change; if needed, disable 2-col on pages where drag is active.
- **Static file path in service worker**: The cache assets list references `/static/...` paths. If `STATIC_URL` is ever changed, this list must be updated. For MVP, `/static/` is the permanent path.
- **Rollback**: Manifest/SW views are purely additive. Remove the two URL entries and delete `pwa_views.py` to revert. CSS/JS changes are self-contained. No DB migrations.
